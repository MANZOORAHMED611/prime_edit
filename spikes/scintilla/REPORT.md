**Status:** throwaway spike, branch `spike/scintilla-qt6` (from `origin/master` 4d35896). Never merged.
**Date:** 2026-11-28
**Machine:** Ubuntu 22.04 (Pop!_OS), 80 cores, Qt 6.2.4, g++ 11.4.0, CMake 3.22.1, Ninja 1.13.0
**Author:** Abdullah (spike). The orchestrator transcribed this file from the spike's hand-back, because the harness blocks subagents from writing report files. Raw command output for every number is in `evidence/`, and images are in `screenshots/`.

## 3. Build

Missing on this machine. Each was unpacked into scratch directories with `apt-get download` + `dpkg-deb -x`; nothing was installed and no sudo was used.

| Missing | Needed by | Production answer |
|---|---|---|
| `libgl-dev` headers | any CMake consumer of `Qt6::Gui` | already in `BUILD.md` |
| `libqt6core5compat6(-dev)` 6.2.4 | `ScintillaEditBase` uses `QTextCodec` on Qt 6 | new `.deb` Depends, or patch `QTextCodec` out (PrimeEdit would feed UTF-8 only) |
| `qt6-wayland` 6.2.4 | native Wayland (today's PrimeEdit runs through XWayland) | `Recommends: qt6-wayland` |

```bash
spikes/scintilla/fetch_sources.sh $SCRATCH/downloads $SCRATCH/src-extract
cmake -S spikes/scintilla -B $SCRATCH/spike-build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DSCINTILLA_DIR=$SCRATCH/src-extract/scintilla -DLEXILLA_DIR=$SCRATCH/src-extract/lexilla \
  -DOPENGL_INCLUDE_DIR=$SCRATCH/gl-root/usr/include \
  -DQt6Core5Compat_DIR=$SCRATCH/c5-root/usr/lib/x86_64-linux-gnu/cmake/Qt6Core5Compat
ninja -C $SCRATCH/spike-build -j60     # [191/191] ... build wall=17.20s
```

`CMakeLists.txt` mirrors both upstream `.pro` files. It builds static `scintilla_qt` (33 core files plus the Qt layer, with AUTOMOC) and static `lexilla` (all 125 lexers; `CreateLexer()` is called directly, no dlopen).

The demo (`demo/`) supports `--selftest`, `--bench FILE`, `--open FILE`, `--html` and `--ime-log FILE`.

## 4. Gate 2 — IME

Set-up: private displays only (Xvnc `:71` with Xephyr `:72` nested inside it), a private `dbus-run-session` + `ibus-daemon` under an isolated HOME, and Weston 9 nested for Wayland with the unpacked `qt6-wayland` plugin. Script: `scripts/ime_test.sh`. Output: `evidence/ime_x11.txt` and `evidence/ime_wayland.txt`. Both show the identical preedit sequence and the commit `你好`.

**Finding.** ibus names its abstract socket after `$TMPDIR`. A long path is cut at the 108-byte `sun_path` limit, and Qt then never connects. Use `ibus-daemon --address=unix:tmpdir=$XDG_RUNTIME_DIR` with a short directory in any IME test harness.

**Not covered:** fcitx; a real GNOME/KDE compositor.

## 5. Gate 3 — large files

Test files:
- `test_500mb.txt`: 500,000,016 B, 5,759,898 lines.
- `test_100mb.txt`: 100,000,029 B, 1,162,197 lines.
- `tests/100mb.json`: 97,101,395 B on **one line**.

Comparison build: PrimeEdit Release from master 4d35896, run fully isolated. The demo loads the way Notepad++ does: `SCI_CREATELOADER(size, SC_DOCUMENTOPTION_TEXT_LARGE)`, 16 MB `AddData` chunks, no lexer.

**Master bug found.** PrimeEdit cannot reach the end of a file over 50 MB. Ctrl+End and dragging the scrollbar to the bottom both stop at the end of the 2 MB preview (line 24,804 of 5.76 M). By the time the editor is shown, the scrollbar range that `Editor::loadViewportContent` relies on has been replaced by QPlainTextEdit's own range. This is a bug in master whatever happens with the migration.

**Verdict: PARTIAL.**
- **Multi-line large files are a step change:** the whole file is editable in 0.5–2.5 s. The memory cost is 2.3× file size with styles, or 1.36× with `STYLES_NONE` (use this above a threshold, as Notepad++ does).
- **One huge line fails:** layout is done in full before the first paint, and layout threads don't help. The migration must keep a long-line fallback.

## 6. Gate 4 — integration API (`demo/changetracker.*`, `demo/toysave.*`, `evidence/selftest.log`)

```
CHECK lsp_incremental  PASS 16 changes replayed; shadow == buffer: 1
CHECK git_gutter_lines PASS gutter marker lines from SCN_MODIFIED: {0,1,2}
CHECK dirty_flag       PASS SAVEPOINTLEFT -> REACHED -> LEFT -> REACHED
CHECK toysave_whole    PASS bytes=268441092 VmRSS delta 64 kB, write+fdatasync+commit 277.0 ms, sha256 match
CHECK toysave_chunked  PASS bytes=268441095 VmRSS delta 0 kB, 359.2 ms, sha256 match
      contrast: SCI_GETTEXT full copy moves VmRSS by 262152 kB
CHECK undo_grouping    PASS grouped 1 undo, ungrouped 5
```

- **(a)** Add `SC_MOD_BEFOREDELETE` to the event mask; it is the only moment a deleted range can still be converted to line and column. `SCI_COUNTCODEUNITS` gives the UTF-16 columns LSP needs. Markers move with their lines. Notifications arrive synchronously inside the edit, so the LSP client must queue them. Today `lspbridge.cpp:170` sends the full text on every change.
- **(b)** `Document::writeAtomic` can take `QByteArray::fromRawData(SCI_GETCHARACTERPOINTER, SCI_GETLENGTH)` unchanged for UTF-8 files with untouched line endings. Other encodings and EOL conversion need one encode pass, as they do today. The chunked `SCI_GETRANGEPOINTER` path avoids moving the gap. Today's path makes three copies.
- **(c)** Undo grouping behaves as specified.

**Test-harness note.** `ScintillaEditBase::keyPressEvent` reads `QApplication::keyboardModifiers()`, not `event->modifiers()`. Synthetic Ctrl/Alt `QKeyEvent`s therefore don't trigger Scintilla bindings. Tests must call `SCI_*` commands, or use real input events.

## 8. Gate 6 — Arabic/English (info only)

- `SCI_SETBIDIRECTIONAL` has no effect on Qt (`PlatQt.cpp` does not advertise `Bidirectional`).
- Typed and pasted mixed text round-trips exactly.
- Rendering is correct with no lexer. With the C++ lexer, style runs are positioned separately and the Arabic overlaps the following Latin text.
- This regresses today's `Editor::updateTextDirection` handling. The owner has ruled it not deciding.

## 10. Risks

1. **Single huge lines:** a 55 s freeze at 97 MB. Mitigation: detect lines over about 1 MB and use a read-only preview or reflow path, tested on `tests/100mb.json`.
2. **Memory:** 2.3× file size with styles, 1.36× with `STYLES_NONE`. Mitigation: drop styles and the lexer above a size threshold; use a read-only mapped view above available memory.
3. **Save-path regression (high-risk).** Scintilla's buffer becomes authoritative. Mitigation: `writeAtomic` is reused unchanged, and the P1.11/P1.12 suites are the gate.
4. **New package dependencies:** `libqt6core5compat6` (Depends, unless `QTextCodec` is patched out); `qt6-wayland` (Recommends).
5. **Bidi rendering regression** (accepted by the owner).
6. **Embedded CSS** is not highlighted (Notepad++ parity likely).
7. **Test harness:** global modifier state (§7).
8. **Upstream cadence:** pin by sha256 and bump deliberately.

## 11. Recommendation

**Proceed with option A.** All four feasibility gates are met for real-world files. The large-file result is a strict improvement over master.

Conditions for the migration spec:
- (a) a long-line fallback, tested on `tests/100mb.json`;
- (b) `STYLES_NONE` + no lexer above a threshold, with a memory budget per file size;
- (c) the save-path change limited to feeding `writeAtomic` from `SCI_GETCHARACTERPOINTER`, with the Phase-1 save suites as the gate;
- (d) `libqt6core5compat6` and `qt6-wayland` added to packaging;
- (e) the bidi and embedded-CSS gaps recorded as accepted limitations or later items.

File the §5.2 master bug separately.
